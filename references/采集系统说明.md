# 采集系统说明

本文档说明杭州租房爆款内容采集系统的架构、数据流和使用方法。

## 系统架构

采集系统由两个核心模块组成：

### 1. trending_collector.py（热门内容采集器）

**位置**：`src/content/trending_collector.py`

**功能**：
- 使用 Playwright 异步浏览器自动化技术，从小红书和抖音平台采集杭州租房相关的热门帖子
- 支持多账号轮换采集（小红书：xhs_01/xhs_02，抖音：dy_01/dy_02）
- 按关键词搜索并尝试按热度排序
- 提取帖子标题、作者、点赞数、评论数等关键数据
- 结果以 JSON 格式存储到 `data/trending/` 目录

**搜索关键词配置**：
- 小红书（5 个关键词）：杭州租房、杭州租房攻略、杭州租房避坑、杭州整租、杭州合租
- 抖音（3 个关键词）：杭州租房、杭州租房vlog、杭州看房

**采集流程**：
1. 启动持久化浏览器上下文（保存登录态）
2. 导航到搜索页面
3. 尝试点击"最热"排序按钮
4. 滚动页面触发懒加载（小红书滚动 4 次，抖音滚动 5 次）
5. 使用 JavaScript 解析搜索结果卡片
6. 提取标题、作者、点赞数、评论数、链接等字段
7. 按 URL 去重后保存到 JSON 文件

**数据字段**：
```json
{
  "title": "帖子标题",
  "author": "作者名称",
  "likes": 1234,
  "comments": 56,
  "shares": 0,
  "favorites": 0,
  "url": "帖子链接",
  "platform": "xiaohongshu 或 douyin",
  "keyword": "搜索关键词",
  "collected_at": "采集时间戳"
}
```

### 2. pattern_analyzer.py（内容模式分析器）

**位置**：`src/content/pattern_analyzer.py`

**功能**：
- 读取 `data/trending/` 下所有 JSON 采集数据
- 筛选高互动帖子（点赞+评论前 20%）
- 分析以下 6 个维度的内容模式：
  1. **标题模式**（8 种）：数字+场景、痛点+方案、反差对比、紧迫感、身份共鸣、提问引导、数字列表、真实体验
  2. **开头钩子**（12 种）：数字开头、月租价格开头、情绪词开头、疑问词开头、身份/称呼开头、地名开头、场景词开头、时间词开头、反差词开头、警告词开头、推荐词开头
  3. **热门标签**：从标题中提取的 #话题标签
  4. **热门话题**（7 类）：价格/性价比、避坑/防骗、攻略/指南、房源展示、生活体验、区域推荐、毕业季/新杭州人
  5. **Emoji 使用频率**：统计标题中常用的 emoji 字符
  6. **内容统计**：平均标题长度、平均点赞数、平均评论数等

**输出**：`data/trending/patterns.json`

## 如何触发手动采集

### 方法 1：直接运行采集模块

```bash
cd "C:\Users\ROG\Documents\阿里agent\小红书抖音自动运营工具"
python -m src.content.trending_collector
```

这会执行全量采集（小红书 5 个关键词 + 抖音 3 个关键词），结果保存到 `data/trending/`。

### 方法 2：运行分析模块

```bash
cd "C:\Users\ROG\Documents\阿里agent\小红书抖音自动运营工具"
python -m src.content.pattern_analyzer
```

这会读取所有已采集的 JSON 数据，筛选高互动帖子，分析模式，输出 `patterns.json`。

### 方法 3：完整流程（采集+分析）

```bash
cd "C:\Users\ROG\Documents\阿里agent\小红书抖音自动运营工具"
python -m src.content.trending_collector && python -m src.content.pattern_analyzer
```

先采集数据，再分析模式，生成最终的 `patterns.json`。

## 注意事项

1. **登录态依赖**：采集器使用 Playwright 的持久化浏览器上下文，需要先在 `data/browser_data/` 目录下有有效的登录 cookie。首次使用需手动登录一次。

2. **反爬机制**：采集器通过以下方式规避反爬：
   - 随机延迟（3-5 秒）模拟人工操作
   - 使用真实浏览器指纹
   - 限制单关键词最大采集数（40 条）
   - 滚动页面触发懒加载

3. **数据去重**：同一天的多次采集会自动合并去重（基于 URL），不会产生重复数据。

4. **降级解析**：如果 JavaScript 提取失败，采集器会尝试正则表达式从 HTML 中提取基本信息，确保数据不会完全丢失。

5. **数据新鲜度**：建议每日采集一次，保持数据的时效性。`patterns.json` 中的 `updated_at` 字段可用于判断数据新鲜度。
